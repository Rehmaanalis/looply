The Browser Rendering Pipeline Demystified

Every frame rendered by modern web browsers passes through three core phases: Layout (Reflow), Paint, and Composite. Animating non-composite properties such as top, left, width, or margin forces the browser engine to recalculate geometry across the entire DOM tree on every frame.

Looply strictly generates transforms utilizing translate3d(x, y, 0), rotate, scale, and opacity. These properties promote the target layer to an independent compositor layer in Chromium and WebKit, allowing direct GPU execution with zero reflows.

Eliminating Main-Thread Frame Drops

JavaScript animation engines (like GSAP or Framer Motion) run requestAnimationFrame on the main thread. When your React app re-renders, parses large JSON, or executes third-party scripts, animations drop frames and feel sluggish. 

/* Pure Compositor Execution - Runs even if Main JS Thread is 100% Locked */
.looply-layer-card {
  will-change: transform, opacity;
  animation: looply-anim-float 3s cubic-bezier(0.42, 0, 0.58, 1) infinite;
}

@keyframes looply-anim-float {
  0%   { transform: translate3d(120px, 40px, 0) scale(1); opacity: 1; }
  50%  { transform: translate3d(120px, 20px, 0) scale(1.05); opacity: 0.9; }
  100% { transform: translate3d(120px, 40px, 0) scale(1); opacity: 1; }
}
